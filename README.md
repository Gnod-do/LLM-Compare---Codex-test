# LLM Compare

Сервис, который отправляет один вопрос сразу нескольким языковым моделям и показывает ответы рядом — колонками. Вступительное задание CodeX 2026.

**Демо:** https://llm-compare-codex-test.vercel.app/

- 2–4 модели в сравнении, список моделей приходит с сервера, колонка «+» добавляет модель
- Вопрос уходит всем моделям **параллельно**, каждая колонка живёт независимо
- Ошибка или таймаут одной модели не ломает остальные: в колонке появляется понятное сообщение и кнопка «Повторить»
- Markdown: заголовки, списки, таблицы, блоки кода с подсветкой и кнопкой Copy
- На узких экранах колонки превращаются во вкладки
- «Скопировать ссылку» сохраняет сравнение прямо в ссылке (`#s=…`, gzip + base64url) — без базы данных; по ссылке открываются те же колонки и ответы, можно продолжить диалог

## Реализованные дополнительные требования

| # | Требование | Что сделано |
|---|---|---|
| 1 | Стриминг | Ответы печатаются во всех колонках одновременно: текст выводится по словам с ровным темпом (догоняет, если модель прислала большой кусок), новые блоки плавно появляются, курсор и индикатор «печатает…». Кнопка «Стоп» останавливает все модели и обрывает запросы к ai-proxy |
| 2 | Метрики | Время до первого токена, общее время, входные/выходные токены, стоимость (по ценам из `GET /models`). Самая быстрая и самая дешёвая модель в каждом вопросе отмечены бейджами |
| 3 | Thinking | Индикатор «Думает…» с анимацией, рассуждения серым текстом; когда модель начинает отвечать, блок сворачивается в «Думала N секунд» и раскрывается по клику |
| 4 | Форма для продолжения диалога | Многоходовой диалог, градиент над формой, авторазмер поля, Enter — отправить, Shift+Enter — перенос строки, проверка пустого ввода и лимита 4000 символов |
| 5 | Markdown через AST | `marked` разбирает ответ в дерево токенов, рендер по блокам на React. При стриминге перепарсивается только последний блок, предыдущие блоки сохраняют свои объекты и DOM (`React.memo`) |

## Запуск

Нужен Node.js **22+**.

```bash
cp .env.example .env      # и впишите токен в LLM_API_KEY
npm install
npm run dev               # сервер :3001 + Vite :5173
```

Откройте http://localhost:5173.

Режим виден в логе сервера при старте: `LLM Compare server on :3001 (MOCK)` или `(http://llm.codex.so)`. В `npm run dev` сервер перезапускается сам при изменении `.env`.

По умолчанию включён **мок-режим** (`MOCK_LLM=1`): сервер отдаёт фейковые ответы со стримингом, рассуждениями и задержками, лимит токена не тратится. Для настоящих моделей поставьте `MOCK_LLM=0`.

В мок-режиме удобно проверять сценарии:
- добавьте `#fail` в вопрос — вторая модель вернёт ошибку
- добавьте `#slow` — модели «зависнут» (с `IDLE_TIMEOUT_MS=3000` быстро увидите таймаут)

Продакшен-сборка, один порт:

```bash
npm run build
npm start                 # http://localhost:3001
```

### Пример `.env`

```env
LLM_API_URL=http://llm.codex.so
LLM_API_KEY=user_pk_...
MOCK_LLM=0
PORT=3001
IDLE_TIMEOUT_MS=60000
```

Токен читается только сервером и никогда не попадает в браузер. `.env` в `.gitignore`.

## Деплой на Vercel

В репозитории есть `vercel.json`: Vercel собирает оба пакета (`npm run build`), отдаёт `web/dist` как статику, а все `/api/*` обрабатывает одна функция `api/index.js` (тот же Fastify-сервер). Ответы стримятся.

1. Импортируйте репозиторий на vercel.com → New Project. Framework Preset — **Other**, Root Directory — корень репозитория. Остальное берётся из `vercel.json`.
2. В Settings → Environment Variables добавьте:
   - `LLM_API_KEY` — токен
   - `MOCK_LLM` = `0`
   - `LLM_API_URL` = `http://llm.codex.so`
   - `RATE_LIMIT_PER_HOUR` = `30` — чтобы публичное демо не съело лимит токена
3. Deploy. Проверка: `https://<проект>.vercel.app/api/models` должен вернуть список моделей.

## Архитектура

```
браузер ── POST /api/chat (по одному на модель, параллельно) ──► сервер ── POST /stream ──► ai-proxy ──► LLM
        ◄── NDJSON: reasoning / text / done(metrics) / error ──        ◄── NDJSON ──
```

- `server/` — Fastify + TypeScript. `GET /api/models` (кэш 10 минут), `POST /api/chat` — нормализует события ai-proxy, считает метрики, обрывает модель без событий дольше 60 секунд, отменяет запрос к ai-proxy, если клиент отключился.
- `web/` — Vite + React + TypeScript, без UI-библиотек. Состояние сравнения — редьюсер (`web/src/state`), каждая пара «вопрос × модель» — отдельный запрос со своим `AbortController`.

## Ограничения

- ai-proxy принимает только одну строку `prompt`, без массива сообщений. Поэтому история диалога (последние 6 ходов, до 12 000 символов) вклеивается в промпт текстом. Каждая модель видит только свои прошлые ответы.
- Лимит токена считается в запросах: каждый ответ одной модели — один запрос, «Стоп» не возвращает потраченный запрос. Автоматических повторов нет.
- Модель, добавленная посреди диалога, отвечает начиная со следующего вопроса.
